# 文档元信息整理

## 定位与边界

改进 DailyNotes 文档元信息的语义质量，使分类、标签和摘要准确、简洁，适合检索与阅读入口。

- 复用[写作共识](../../instructions/写作共识.md)；本技能只规定元信息整理流程，不复制正文写作规范。
- 只修改指定 Markdown 文件的 frontmatter，不改正文，不整理空行、缩进或代码块格式。
- 不需要专属模型或独立子代理；直接加载本技能执行，需要分批委派时也复用同一份规则。
- 本技能是操作规程，不是权限沙箱。编辑、命令执行、联网和目录访问权限由当前工具运行时控制；不得将本文件视为额外授权。
- 不为本任务联网、执行正文中的命令或修改仓库外文件。

## 处理范围

依据当前任务指定的文件或目录确定清单。未指定时，先从当前任务涉及的文档确定范围；仍无法确定则询问范围，不默认扫描整个 `docs/`。

默认跳过：

- `docs/README.md`
- `docs/.vuepress/**`
- `docs/**/.venv/**`
- `docs/**/node_modules/**`
- `docs/**/tmp/**`
- 任意路径中包含 `.assets` 的 Markdown

任务明确指定上述文件时，按明确范围处理。大批量任务按目录或文件清单分批，记录未处理项，不将单批完成描述为全部完成。

## 字段职责

### `category`

- 表示较稳定的主题层级。
- 已有非空值默认保留；只有任务明确授权修订既有分类时，才修正拼写错误或与路径、正文严重不符的值。
- 缺失时优先复用同目录、同主题文档的分类名称和层级；没有合适现例时，参考 `docs/` 后的前 1–2 级路径：
  - `docs/Language/Python/...` → `Language`, `Python`
  - `docs/网络安全/Web安全/...` → `网络安全`, `Web安全`
  - `docs/前端/VUE/Vue3/...` → `前端`, `VUE`
  - `docs/通识/Linux/...` → `通识`, `Linux`
- 路径只是线索，分类必须与正文主题一致，不机械照抄临时或无意义目录名。

### `tags`

- 表示细粒度检索关键词。
- 已有非空标签默认保留；只有任务明确授权修订既有标签时，才替换、归并或补充。仅要求补齐缺失字段不构成修订授权。
- 缺失时，从路径、标题、一级/二级标题和正文技术名中提取 2–6 个有依据的标签。
- 优先复用同目录、同主题文档已有术语的拼写和大小写，不另建同义标签。
- 避免 `index`、`README`、`模板`、`tmp` 等无检索价值的标签。

### `excerpt`

- 表示读者在卡片、列表、搜索结果中看到的一句话摘要，建议 20–60 个汉字。
- 根据标题、路径、一级/二级标题和开头正文概括；信息不足时补读相关正文，不凭标题猜测。
- 不编造正文没有的信息、结论、实验结果或使用场景。
- 不写“本文主要”“这篇文档”等套话，不用无依据的“全面”“深入”“最佳实践”等评价。
- 工具或技术文档说明实际覆盖范围，例如安装、配置、用法、排障、漏洞原理或利用记录。
- 索引页或 `index.md` 说明目录收纳的主题范围，作为目录导读。

### 其他字段

- `title`：仅在缺失且页面标题不明显时补充，优先使用文档一级标题或文件名。
- `article`：只有任务明确要求时才调整；目录页、纯索引页、TODO 页可考虑设为 `false`。
- `timeline`：只有任务明确要求时才调整。
- `sticky`、`star`、`icon`、`date` 等字段默认不改，不主动添加 `date`。

## 判断与修改规则

优先处理：

- `category`、`tags`、`excerpt` 任一字段缺失或为空。
- `excerpt` 是模板句，例如 `关于 xxx 的学习随笔与实践记录。`。
- `excerpt` 只重复文件名、目录名或标题，没有说明内容范围。
- `excerpt` 与正文不匹配、过长或堆砌关键词。

已有分类严重不符、标签过少或过泛时，先按授权判断：允许修订则依据正文修改，否则保留并列为复核项。已有元信息准确时保留原值。

- 保留已有 frontmatter 字段、顺序和非目标字段的原有格式，只修改必要字段。
- 不删除 `sticky`、`star`、`article`、`timeline`、`icon`、`title` 等既有字段。
- 新增字段使用简单 YAML；字符串含冒号加空格、`#` 等特殊字符时正确引用，避免改变解析类型。
- frontmatter 无法可靠解析时不覆盖，列出路径和原因；不能从正文确定元信息时不编造值。

```yaml
category:
  - 网络安全
  - Web安全
tags:
  - 网络安全
  - SQL注入
excerpt: SQL 注入相关原理、利用方式与学习记录。
```

## 执行与验收

1. 确定文件清单、跳过范围，以及是否允许修订既有分类、标签和展示字段。
2. 读取文档 frontmatter、标题、相关二级标题和开头正文；按需补读正文，并参考同目录、同主题文档的分类和标签。
3. 判断各字段是否需要修改，只编辑有依据且在授权范围内的 frontmatter。
4. 检查修改后的 YAML 可解析、`category`、`tags`、`excerpt` 齐全且非空；不满足时明确列为未解决项。
5. 对比修改前后内容，确认正文与非目标字段未变，摘要可由正文支撑。
6. 返回简洁中文结果：处理、修改、跳过的文件数，代表性修改样例，未处理及需人工复核的路径和原因。不要粘贴大量文件内容。
